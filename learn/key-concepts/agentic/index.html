// REASONINGLIVE

Chain-of-Thought

CoT · STEP-BY-STEP

The model writes out its reasoning before the answer. Each step accumulates context for the next; the final answer is the conclusion.

// PROMPTINGLIVE

In-Context Learning

ZERO · ONE · FEW-SHOT

Give the model task examples in the prompt itself. More examples = better pattern matching, no weights changed.

// RETRIEVALLIVE

RAG

RETRIEVAL-AUGMENTED GEN

Embed the query → search a vector DB → inject top-K chunks into the prompt → generate. The model "looks up" knowledge it doesn't have to memorize.

// PROTOCOLLIVE

MCP

MODEL CONTEXT PROTOCOL

A standard way an agent talks to external tools and data sources. One protocol, many servers — filesystems, browsers, databases, code runners.

// FINE-TUNINGLIVE

LoRA / QLoRA

h = Wx + BAx · low-rank Δ

Freeze the big base weights W. Train only two tiny matrices A and B whose product BA approximates the update. Massive parameter savings.

// AGENT LOOPLIVE

ReAct Loop

THINK · ACT · OBSERVE · REFLECT

An agent runs a cycle: reason about the goal, take an action, observe the result, reflect, then repeat. The substrate of modern tool-using LLMs.

// PRETRAIN ONCELIVE

Foundation Model

PRETRAIN · ADAPT · DEPLOY

Train one massive model on broad data, then adapt it to many tasks via fine-tuning or prompting. The base is shared; task heads are cheap.

// SPARSELIVE

Mixture of Experts

MoE · TOP-K ROUTING

A router picks a small subset of experts per token. Compute scales with the active ones, not the total — sparse activation, dense capacity.
